# 测试指南

项目使用 Java 21、Spring Boot 3.5 和 Maven。根 `pom.xml` 为各 Java 模块统一提供 `spring-boot-starter-test`（JUnit Jupiter、AssertJ、Mockito、Spring Test 等），测试依赖的作用域均为 `test`。

## 单元测试

- 测试代码放在对应模块的 `src/test/java`，类名以 `Test` 结尾。
- 纯业务逻辑优先使用 JUnit Jupiter + Mockito，不启动 Spring 容器；需要验证 Spring 配置时再使用 Spring 测试注解。
- 运行全项目：`mvn test`
- 运行单个模块及其依赖：`mvn -pl ara-module/ara-module-system -am test`
- 运行指定测试：`mvn -pl ara-module/ara-module-system -am -Dtest=SysDeptServiceImplTest -Dsurefire.failIfNoSpecifiedTests=false test`

`SysDeptServiceImplTest` 是一个真实回归用例：禁用部门及其子部门不会出现在用户可选的部门树中。Surefire 3.5.4 负责在 `test` 阶段发现并运行 JUnit 5 测试。

## 集成测试

`ara-server` 的测试依赖提供 Testcontainers JUnit 扩展、MySQL 容器、通用容器（可用于 Redis），以及 Spring Boot 的 Testcontainers 集成。版本由 Spring Boot 3.5.0 的 BOM 管理。集成测试需要可用的 Docker 环境。

- 集成测试类名以 `IT` 结尾，放在 `src/test/java`。
- `mvn test` 只运行单元测试；运行集成测试使用 `mvn -P integration-tests verify`。
- 涉及项目的动态数据源或自定义 Redis 配置时，通过 `@DynamicPropertySource` 注入容器地址和端口；不要假设 `@ServiceConnection` 能自动覆盖自定义配置。
- 用 MySQL 容器验证数据库行为，避免用 H2 代替 MySQL 后漏掉方言差异。

目前只接入基础设施，没有引入数据库初始化脚本，也没有要求每次本地构建启动 Docker。
